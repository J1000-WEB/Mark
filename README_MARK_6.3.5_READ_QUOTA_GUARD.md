# MARK 6.3.5 — 주간 조회 Quota 보호

## 문제
- `Quota exceeded for quota metric 'Read requests per minute per user'` 발생.
- 주간 대시보드가 화면 진입/실시간 갱신/스냅샷 목록 조회 때 `Weekly_History`, `Weekly_Store_History`, 시트 메타데이터를 반복 조회하고, 실시간 갱신 중 상품 히스토리까지 다시 저장하면서 Google Sheets 읽기 요청이 급증함.

## 수정
1. 주간 매출 대시보드 실시간 조회는 아래 원본 2개만 사용
   - 기준일·상품 TOP: `금주/전주!B2` 및 금주/전주 시트
   - 점포별 매출: `MARK_DB / 일간매출(26년)`
2. 대시보드 조회/실시간 갱신에서 `Weekly_History`, `Weekly_Store_History` 자동 저장 및 대용량 읽기 제거
3. 동일 원본 시트는 서버 인스턴스에서 45초 캐시 및 동시 요청 공유
   - 실시간 갱신 버튼은 캐시를 우회하여 원본을 강제 재조회
4. 스냅샷 목록/상세 조회는 45초 캐시
5. 실시간 갱신 후 스냅샷 목록을 불필요하게 재조회하지 않음
6. 히스토리 시트의 생성/헤더 갱신은 조회가 아니라 실제 저장(upsert) 시에만 수행

## 기대 효과
- 평상시 주간 화면 1회 조회 시 Sheets Read 요청 수를 크게 줄임
- `실시간 갱신`은 선택한 주차의 원본만 재조회
- `Weekly_History`는 판매데이터 전용 스냅샷으로 분리하고, 주간 매출 KPI/점포순위는 계속 `일간매출(26년)` 단일 기준 유지
